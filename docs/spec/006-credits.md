# 006 片頭與片尾名單

狀態：READY。

## 1. 為什麼

新局開始前的片頭名單與破關後的片尾名單，由名單程式逐行以大字型畫出，不經 docs/spec/004 接手的文字 routine，以英文顯示。職稱與遊戲角色名要顯示中文，公司名與真人姓名保留原文。

## 2. 證據

輸入：`CSPPRG.EXE`（SHA-256 見 `workplace/disc/manifest.json`）；第一章程式段傾印 `workplace/runs/seg188b-ch1.bin`（SHA-256 `14d1ce6b…8891da`，docs/re/006）與反組譯 `seg188b-ch1.asm`；實機 `credits-r`（`--cycles 1000`，`--trace-at 89e8,8a07`，`--dump-ram 881500000`）。位址為 load segment 188Bh 內偏移。

| 位置 | 原始位元組與指令 | 角色 | 等級 |
|---|---|---|---|
| `231e`–`2356` | `ba 76 08`／`ba 80 08` 選字型 `POLC.SQX`／`POLCG.SQX`；`ba 5f 08`／`ba 54 08` 選 `GENEZ.SQX`／`GENEA.SQX`（`[0e19]` 不為 0 時取後者） | 載入名單字型與名單腳本 | 已證實（反組譯與資料段字串） |

## 3. 行為

- 接手點 `8a07`：讀 DS:SI 到第一個小於 20h 的位元組為英文行，y＝CX，中心＝`89e8` 時記下的 DI，模式＝堆疊頂的字。模擬 `pop dx`（DX＝堆疊頂，SP＋2），IP 設為 `8a26`，原版跳過這行的繪字、照常找下一行。英文原版模式（passthrough）不接手。
- 比對鍵：英文行連續空白縮成一個、去頭尾空白，前綴 `credits:`，查同一份譯文表（`text/credits.zh-TW.tsv`）。前綴避免與章節片語撞 key。查不到就畫英文原文（真人姓名、公司名不列在表裡）。
- 顯示：以中心 x、y 畫一行，字高為原版 14 像素乘倍率，字色固定 (210,172,100)，黑色圓角描邊。透明度：模式 bit 15 為 1（淡入）時為 (11−低位元組)/11；為 0（淡出）時為低位元組/10，為 0 即移除。同一 y 的新行取代舊行。
- 事件紀錄：每次接手記一列，kind 為 `Credit`、site 為 `8a07`。

## 4. 驗收

- 片頭：開新局時名單每一頁的英文都不畫；職稱與角色名以中文顯示，姓名以覆繪字型照原文顯示，跟著原版的淡入淡出出現與消失。
- 英文原版模式下名單照原版畫。
- 片尾（GENEZ）：正常由腳本變數程式在值為 F0h 時於 `4f82` 呼叫 `231e`（`[0e19]`＝0 時選 POLC 與 GENEZ）。取證以 `kgb-run --end-credits 673232800` 在第一章辦公室載入後最後一次進入 `4d19`（推完 bx、dx、di 的 `4d1c`）時改 IP 到 `4f82`，堆疊與 `50ff` 收尾對稱，只改 IP。實測 endcred-4：片尾 34 個職稱與角色名全部命中，`# T` 頭像在左右兩側時名字分別以 x＝240、80 置中，不遮頭像；endcred-5 截圖目視確認。背景是觸發當下的辦公室，與正常破關不同。
- 只把 `231e` 改走片尾分支（開新局時）會在第一個 `# T` 當掉：頭像需要的 `[06f8]` 資料與驅動指標此時還沒就緒（endcred-1）。
