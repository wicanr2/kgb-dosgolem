# 004 KGB 文字 routine 接手

狀態：READY（§2、§3、§5）。§5 只涵蓋 mode 13h 鏈結畫面。

## 1. 為什麼

使用者定案（2026-10-29）：接手文字 routine、跳過原版英文繪字、中文畫在 3 倍覆繪層。原版字幕行高 9–12 像素，原生解析度放不下可讀的中文。

## 2. 證據

輸入：`CSPPRG.EXE` SHA-256 見 `workplace/disc/manifest.json`；記憶體傾印 `workplace/runs/rs-r15/out/ram.bin`（自有核心 50,000,000 步）。解壓後的程式碼在 load segment（PSP＋10h，本次 188Bh）。反組譯工具 `objdump -m i8086`（binutils，`dosgolem-rust-sc:1.99.1-r1`），位址為 load segment 內偏移。推論等級在每列註明；IDA 交叉驗證列在 worklist `ida-text-routines`。

| 偏移 | 簽章（16 bytes） | 角色 | 等級 |
|---|---|---|---|
| `86e9` | `50 52 56 55 06 53 51 8d 31 8b 4d 02 2b cb bb 00` | 文字區塊：DI＝區塊（+2 結尾索引、+4 寬度），BX＝起始索引，CX＝x，DX＝y，BP＝最多行數。以 `^` 或 0 分行，依行數上移 y，逐行量寬置中後呼叫 `87d8`，行距 `[7691]`。保存並還原 AX、DX、SI、BP、ES、BX、CX | 強推論 |
| `87d8` | `fc 55 56 06 8a 36 0e 44 8b f7 8b f9 8b cb ac 3c` | 單行：DS:DI＝字串，CX＝x，BX＝y，顏色 `[440e]`。逐字以 `87c2` 取寬、經 `lcall es:[054a]`（ES＝2144h）畫字形。結束時 DI＝結尾字元之後、CX＝輸入 BX、DH＝`[440e]`、AL＝結尾字元（0 或 `^`） | 強推論 |
| `2c40`–`2cf0` | `bf 34 44 c7 45 02 08 00 c7 45 06 00 00 b8 40 01` | 開場字幕：從全文 `[0644]` 複製一句到區塊 4434h（遇 `. ; : ? !`、`^`、0 結束），顯示時間＝字數×`[0654]`÷16，於 `2ce5` 呼叫 `86e9`（CX＝0、DX＝B5h、BP＝2） | 強推論 |

- `86e9` 的呼叫點：`2ce5`、`529d`、`584c`、`7727`。
- `87d8` 的直接呼叫點：`1d94`、`2a82`、`3e10`、`69c9`、`86b0`，以及 `86e9` 內的 `875f`。
- 字形像素（驅動 `51e0:12d1`，由 `lcall es:[054a]` 經 `51e0:0124` 轉入）：每個像素一個位元組，0 為透明；低半位元組非 0 時寫 `DH＋(值 & 0Fh)`，DH＝`[440e]`；低半位元組為 0 時寫 0（黑色陰影）。開場字幕 `[440e]`＝254，傾印中字幕像素為 255（590 個），一行頂端 y＝187＝181＋(2−1)×6。已證實（程式碼與傾印一致）。
- 字型狀態：`[768f]` 字型段、`[7691]` 行高（9、10、12）、`[7693]` 字距，由 `8774`、`8789`、`879e`、`87b3` 切換。

## 3. 攔截契約

- 只接手 `TAKEN_SITES` 列出的呼叫點（返回偏移）：`2ce8` 開場字幕、`1d97` 章節標題列、`52a0` 地點標籤、`584f` 旁白（kgb-r9、kgb-r10 取證）。其他呼叫點只記錄事件、CPU 不變、原版照畫；例如 `86b3` 時鐘用特殊數字字型，不接手。
- 每步執行前，若 CS＝load segment 且 IP 為 `86e9` 或 `87d8`，先比對該處 16 bytes 簽章，不符就不攔截並記錄一次「簽章不符」。
- `86e9`：讀 DS:DI 區塊的 `[BX, [DI+2])` 位元組為原文，連同 CX、DX、BP、`[7691]`、`[440e]`、`[768f]`、呼叫點（堆疊頂的返回偏移）記成文字事件，然後模擬近返回（彈出 IP）。
- `87d8`：返回偏移為 `8762`（`86e9` 內部）時不會發生，因為外層已被攔截。其他呼叫點：讀 DS:DI 起到 0 或 `^` 的原文記成事件，設定 DI、CX、DH、AL 如 §2 表，ZF＝1，再模擬近返回。
- 不寫入原版記憶體；只改 CPU 暫存器與 SP。

## 4. 文字事件

`{步數, 種類(block/line), 呼叫點, 原文 bytes, x, y, 最多行數, 行高, 顏色索引, 字型段}`。原文是比對鍵，譯文表 `text/kgb.zh-TW.tsv` 以原文查找。區塊原文去掉結尾的 0，中間的 0 改寫為 `^`（86e9 對兩者同樣換行）。

## 5. 覆繪生命週期

證據（FerroGolem 探針、原版照畫、監看 A0000 第 181–199 列的寫入；FerroGolem `workplace/runs/kgb-w1`、`kgb-w2`）：

- `51e0:0bcd` 每句把整條字幕帶（19 列 × 320）搬到螢幕一次：80M 步內 6 次、334M 步內 31 次，與第一段 31 句一一對應。最後一次在 #303,720,929，最後一句事件在 #302,922,874。
- 最後一句之後沒有清除字幕帶的搬移；字幕留到換場時 `51e0:0c05` 的整格重繪（#330,140,227 前後）才被蓋掉。

契約（`crates/kgb-cht/src/lifecycle.rs`）：

- 新事件取代同一呼叫點、同一種類的項目。
- 事件後第一波寫到項目範圍的螢幕寫入算上屏；相鄰寫入相差超過 100,000 步視為新的一波，新的一波寫到範圍就移除項目。
- 範圍：區塊為 `[x, x+寬) × [y, y+最多行數×行高+1)`，單行為 `[x, 320) × [y, y+行高)`，以 320×200 畫面計。
- 驗收：`kgb-r8` 跑 334M 步，31 句全部顯示譯文，換場時移除 1 次；畫面確認最後一句在換場前仍在、換場後消失。
- 非 mode 13h 鏈結的畫面尚未量測，遇到時另立規格。

## 6. 驗收

- `crates/kgb-cht/tests/takeover.rs`：以最小 MZ 在真實偏移放簽章、從 `2ce5`、`1d94` 呼叫；`86e9` 跳過後除 IP、SP 外暫存器不變；`87d8` 輸出 DI、CX、DH、AL 符合 §2；簽章不符不攔截（負對照）；白名單外只記錄、CPU 不變。
- 英文退路（沒有譯文時）在覆繪層畫原文，區塊只畫前 `max_lines` 行，與原版相同。
- KGB 開場：事件序列的原文與 `2CF32h` 全文的句子順序一致；畫面上沒有英文字形。
